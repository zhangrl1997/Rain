# 检索 → 标注 → 校验 工作流

本文档定义了研究写作的三大核心工作流环节，所有研究和写作必须遵循。

---

## 一、前置检索（Pre-Research）

每写一个板块之前，必须做至少 2 次独立的检索。

### 检索规则

- **检索次数**：每个板块开始前 ≥ 2 次
- **检索内容**：
  - 第 1 次：搜索板块最核心的事实数据、市场规模、关键玩家
  - 第 2 次：补充搜索，覆盖前一搜遗漏的维度，或验证有疑问的数据
- **检索工具**：优先使用 `/多搜索`（17个引擎聚合）或 WebSearch
- **检索产出**：每搜一次，记录关键发现和来源 URL，作为后续 [N] 标注的依据
- **检索标注**：每次检索到的数据同步标注年份和统计口径（如"2025年A100租赁价"而非"GPU价格"），防止跨年混淆——口径不同的同一数据需在正文中并列呈现

### 数据引用三问

每写一个数字前，在脑子里过三关：
1. **哪一年的？**——标注 `2025A`（实际）/ `2025E`（预测）/ `2023-old`（已过时），防止用旧数据说新情况
2. **谁的？**——标注主体和统计口径（`"台达 ~35%" ≠ "台系厂商合计 ~70%"`），防止不同主体的数字被混淆
3. **和另一来源差多少？**——差异 >20% 时在正文并列呈现并说明口径不同，不强选一个

### 什么叫"一个板块"

一份完整报告的每个一级章节（`##`）算一个板块。例如"市场结构""价值链分析""竞争格局"各算一个板块，每个板块开始前都必须执行前置检索。

## 二、同步标注（Inline Citations）

写作时必须同步标注来源。

### 标注规则

1. **正文标注**：关键数据或事实判断后紧跟 `[N]`，N 按首次在正文出现的顺序递增
   - 标注在句末标点之前，例如：`行业在 2025 年首次突破千亿规模[1]`
2. **参考文献表**：文末按 1→N 顺序列出所有来源，每项带完整 URL
3. **多源处理（重要）**：当多个可信来源对同一数据给出不同数字时：
   - **不要强行只选一个**。把多个数字都列出来，在正文或脚注中说明差异的原因
   - 例如：`不同机构对该市场规模的估算存在差异：QYResearch 估值为 $2.57B，DIResearch 为 $2.85B，差异主要源于统计口径不同（前者仅含便携式电源站，后者纳入相邻品类）[2][4]`
   - 用对比表呈现多源数据尤其有效
4. **推测标注（必须）**：以下情况必须明确标注，不能让读者误以为是来自可靠来源的数据：
   - 你自己的估算或推测 → 标注 `[推测]` 或 `（此为估算，仅供参考）`
   - 基于已知数据的合理外推 → 标注 `[基于……外推]`
   - 没有找到来源的判断性陈述 → 标注 `（作者判断）`
   - 例如：`预计 2026 年市场规模将达 $3.0-4.5B[推测，基于前两年CAGR外推]`
5. **来源要求**：
   - 优先使用可直接访问的官方来源
   - 禁止使用无法验证的来源（需登录、需付费墙绕过）
   - 微信文章、新闻聚合页替换为原始出处

6. **跨源差异处理**：同一数据点从 2-3 个独立来源交叉验证。如果不同来源差异 >20%，把多个数字都列在正文中并说明统计口径不同，不强选一个

### 跨文件标注

如果一份报告分成多个文件写，合并前用 Python 脚本做全局去重和重编号：

```python
text = re.sub(r'\[\[(\d+)\]\]', lambda m: f'[{map[m.group(1)]}]', text)
```

## 三、章节校验（Post-Chapter Verification）

每写完一个 `*.*` 小节立即执行校验，不等整章写完——偏差发现越晚，回溯修正的成本越高。

### 校验方法

1. **独立搜索验证**：对本章引用的关键数据，重新搜索一次，与原文对照
2. **标记结果**：
   - ✅ 确认：数据一致，来源可追溯
   - ⚠️ 部分正确：数据有偏差，需要修正
   - ❌ 错误：数据完全错误，删除或重写
3. **交叉验证**：同一数据点尽量从 2-3 个独立来源交叉验证。不同来源之间的数字分歧本身也是发现，应在报告中注明

### 修正流程

发现问题后：
1. 优先搜索官方/一手数据源替换
2. 更新正文数据和 [N] 编号
3. 更新参考文献表
4. 如果修正影响了后续章节的逻辑判断，需回溯调整

### 跨章合并防错

多章合并为最终报告时，参考文献用脚本一次性处理全流程：
1. 合并前先清理各章参考文献中的"注释"类脏数据（如"注：本章编号..."等无 URL 的行）
2. 用脚本提取所有来源 URL/描述，去重后一次性替换全文 `[N]` 标记
3. **不要**先合并再逐轮手动修补——每轮修补都可能引入新的编号漂移

> 经验教训：对已合并完成的文件做全局替换（如 `sed` 正则替换分隔线）可能意外破坏参考文献编号结构，应避免对结构化内容做非精确匹配的批量替换。

## 四、飞书发布检查清单

### 发布前检查
1. **货币符号 `$` 转义**——markdown 中的 `$120-190B` 会被飞书解析为 LaTeX 数学公式。导入前用脚本将全部 `$` 替换为 `\$`（或构建流程自动处理）
2. **删除不兼容语法**——飞书不支持锚点链接 `(#xxx)` 和脚注 `[^1]`，发布前搜索替换
3. **大表格排版**——导入后打开飞书检查宽表格是否移位，必要时用飞书本地格式校正
4. **标题层级**——检查 `#`→`##`→`###`→`####` 层级完整，无跳级

### 飞书限制备忘
| 特性 | 飞书支持 | 替代方案 |
|------|---------|---------|
| 锚点链接 `(#xxx)` | ❌ | 纯文本编号列表 |
| 脚注 `[^1]` | ❌ | 文末参考文献 `[N]` |
| 代码块 ``` | ✅ | — |
| markdown 表格 | ✅ | 宽表格建议检查排版 |
