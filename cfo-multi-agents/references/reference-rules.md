# 方案文档参考引用规范

所有 Agent 在生成方案/意见/报告时，必须在正文中使用引用编号标注信息来源，并在文档末尾列出完整的参考文献列表。

## 引用编号体系

### 两套独立编号

| 编号 | 适用范围 | 格式 | 示例 |
|------|---------|------|------|
| `[N]` | 公开来源（网页、研报、法规原文、新闻、数据库） | [1], [2], [3]... | 根据XX法规[1]，该架构存在合规风险 |
| `[U]` | 用户/项目内部资料（公司财务报表、尽调资料、内部邮件） | [U1], [U2]... | 该公司近三年收入复合增长率达32%[U1] |

**规则**：两套编号各自独立、各自连续，互不影响。正文中可能同时出现 `[U1][1]` 等混合引用。

### 编号连续性

- `[N]` 从 1 开始按首次出现顺序连续编号
- `[U]` 从 U1 开始按首次出现顺序连续编号
- 同一来源在正文中多次引用时使用**同一编号**
- 多篇文档合并时，需重新统一编号

## 参考文献列表格式

文档末尾必须包含 `## 参考文献` 章节，格式如下：

```markdown
## 参考文献

[1] 标题 — URL
[2] 标题 — URL
[U1] 资料来源名称 — 文件路径或内部说明
[U2] 资料来源名称 — 文件路径或内部说明
```

### 具体要求

| 来源类型 | 要求 |
|---------|------|
| **网页/新闻** | `[N] 标题 — URL`（URL 必须完整可访问） |
| **法规/部门规章** | `[N] 《法规名称》（文号/发文机关，年份）— URL` |
| **案例/判决** | `[N] 案号/案件名称 — 裁判文书网 URL（如有）` |
| **研报/出版物** | `[N] 报告标题 — 机构名称, 日期 — URL` |
| **数据库/行情** | `[N] 数据名称 — 数据库名, 查询日期 — URL（如有）` |
| **用户资料** | `[U1] 资料简称 — 文件路径（如 user/provided/financials.xlsx）` |

## 写作时引用规则

### 基本规则

1. **每条数据/判断必须标注来源**，除非是常识性知识
2. **关键数据点**（金额、增长率、估值区间、税率等）必须标注来源
3. **法规条文引用**必须注明具体条款号和发布机关
4. **推测性分析**（非数据驱动）需标注 `（作者判断）` 或 `[推测]`
5. **多源数据差异 >20%** 时应并列呈现并说明原因

### 搜索要求

- 每一独立数据点至少应有一个可追溯的来源
- 境内投融资/IPO 项目优先引用中国官方来源（证监会、交易所、统计局、财政部、税务总局）
- 境外项目引用国际来源（SEC、HKEX、Bloomberg、Wind 等）

### 各角色特殊要求

| 角色 | 引用侧重 |
|------|---------|
| **券商/投行** | 可比公司估值、市场数据、交易公告、行业研报 |
| **律师** | 法律法规条文号、判决书案号、监管文件号 |
| **审计师** | 会计准则号、审计准则号、财务报表来源 |
| **税务** | 财税文号、税务总局公告号、判例案号 |
| **银行** | 基准利率公告、贷款市场报价、信用评级报告 |

## 跨文档合并时的参考接管

当多份独立的 Agent 意见合并为最终方案时：

1. 各 Agent 按 `[N]` 体系独立编号
2. 合并后需要**重新统一编号**（按首次出现顺序）
3. 总编辑在合并时完成参考接管
4. 最终文档的参考文献表必须经过去重和重新排序
