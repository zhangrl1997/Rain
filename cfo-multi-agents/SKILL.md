# CFO Multi-Agents 协同研究方法论

`methodology.md` 为深度原理参考，在遇到复杂情况时按需读取。

## 角色分工

| 角色              | 职责                  | 设定文件               |
|:--------------- |:------------------- |:------------------ |
| **主控Agent**（你）  | 任务拆解、调度协调、流程把控、最终合稿 | —                  |
| **专业Agent × N** | 各领域独立研究、交叉审核、辩论、修正  | `agents/<角色>.md`   |
| **COO**         | 内部落地评估、激励方案设计、案例对标  | `agents/COO.md`    |
| **编辑**          | 三轮质量审核（格式+逻辑+数据+引用） | `agents/editor.md` |

**交叉审核人默认选律师+COO**（法律框架+内部落地，互补性最强）。审核人不审自己，对称矩阵（A审B则B也审A）。

## 6阶段流程

### 阶段1：派活

**主控执行**：

1. 将研究主题拆解为N个子任务，创建项目文件夹（`研究报告/`、`交叉审核/`）
2. 检查 `.claude/settings.json` 权限白名单是否存在，不存在则由用户创建配置命令
3. 审阅各Agent的人物设定文件（`agents/`目录），补充本项目所需知识缺口
4. Agent读取更新后的设定，确认角色边界
5. 为每个子任务创建Task。**Task须包含引用规范强制要求 + 各Agent约定统一的法规引用版本**
6. 并行启动所有专业Agent

**阶段自查**：

- [ ] 项目文件夹已创建
- [ ] 权限白名单已配置
- [ ] 所有Agent设定已审阅优化
- [ ] 各Agent约定了统一的法规引用版本
- [ ] 所有Task已创建且Agent已启动
- [ ] 每份Agent产出已落盘

### 阶段2：编辑首轮审核

**触发条件**：每份研究报告落盘后**立即**启动编辑审核（不等所有报告完成，**不得攒批**）。

**审核维度**：

- 格式：标题编号规范（## N. / ### N.N）、无代码块、表格对齐、仅一个#一级标题
- 数据一致性：文中数字前后一致、法规引用准确
- 逻辑：各部分无矛盾、无遗漏
- 引用标注：正文[N]标注，参考文献一一对应
- **同文件内部一致性**：同一报告中不同章节对同一事项的描述一致

**输出格式**：✅通过项 / ⚠️需修正（具体位置+建议） / ❌问题项 / 📝总评

**阶段自查**：

- [ ] 每份落盘报告已启动编辑审核
- [ ] 编辑审核意见已同步给对应Agent和主控

### 阶段3：交叉审核

1. 交叉审核人审**所有其他Agent**的产出（不含自己）
2. 审核意见写入 `交叉审核/` 目录落盘
3. 主控将落盘的审核意见转交被审核方
4. 被审核方阅读后，对每条⚠️/❌区分：**接受**（入修改清单）/ **有异议**（入辩论）

**输出格式**：🔗一致/互补 / ⚠️需澄清补充 / 💡建议

**阶段自查**：

- [ ] 交叉审核矩阵完整覆盖
- [ ] 所有审核意见已落盘到 `交叉审核/` 目录
- [ ] 被审核方已确认（区分接受/有异议）
- [ ] 有异议项已标记，准备进入辩论

### 阶段4：辩论

**核心原则**：主控无权替被指控方认罪。此阶段不可跳过。

**主控执行**：

1. 仅处理被审核方"有异议"的争议项，排除纯格式问题
2. **跨报告口径扫描**：提取各报告中涉及"同一事项"的数据和表述对比口径差异，纳入辩论
3. 被审核方"接受"项直接进入修改清单，不进入辩论
4. 争议双方在收件箱直接对谈

**升级路径**：

```
收件箱对谈 → 达成共识 → 写入修改清单
     ↓（无法达成）
双方分歧写入合稿"分歧披露"章节 → 结案
     ↓（某一方沉默）
主控创建Task强制回应 → 仍不回 → 记录"未回应"
```

**辩论格式**：

- 指控方：`@[对方] 关于[位置]：[原文引用]→[我的依据]→请确认或提供反证`
- 被指控方：`@[对方] 关于[指控]：接受/不接受→反证或说明→如需修正的方案`

**阶段自查**：

- [ ] 接受项已确认（不进入辩论）
- [ ] 异议项全部纳入辩论
- [ ] 跨报告口径差异已纳入辩论
- [ ] 每场辩论有明确结论（共识/分歧披露/Task强制回应）

### 阶段5：修改 + 编辑逐份终审

- 各Agent根据辩论结论和编辑首轮意见修改自己的报告
- 按三色分级：**🔴P0**（实质错误，必须立即修）→ **🟡P1**（重要不足，应尽快修）→ **🟢P2**（优化建议，可排期修）
- 涉及数值计算须标注中间步骤，输出前自我验算
- 每份修改完成后，编辑**立即**复核（不等全部改完）

**编辑逐份终审要点**：首轮问题是否修复 / 辩论结论是否反映 / 是否引入新矛盾 / 跨报告数据一致性

**阶段自查**：

- [ ] 每份报告的修正清单已全部处理
- [ ] 每份修正后的报告已通过编辑逐份终审
- [ ] 跨报告矛盾已发现并解决

### 阶段6：合稿 + 编辑合稿复核 + check.sh

- 主控将N份报告整合为一份完整文档，附录列出各专题报告索引
- 编辑复核：跨章节引用是否一致、数据在全文中是否自洽、风格是否统一
- 运行 `bash references/check.sh <合稿文件>` 验证引用完整性

**阶段自查**：

- [ ] 合稿已完成
- [ ] 编辑合稿复核已完成
- [ ] check.sh通过（或差异已标注说明）

## 引用规范

引用规则详见 `references/reference-rules.md`（含[N]公开来源、[U]内部资料两套独立编号体系）。

### 引用编号纪律

1. **新增引用必须追加到文末**，不得在现有[N]编号之间插入
2. 如在中间插入引用，须同步重排后续所有编号并运行check.sh验证
3. **每完成一节或整份报告后，立即运行check.sh**验证编号连续性
4. 每个[N]在参考文献中须有对应条目，每条参考文献在正文中须有引用

## 模板速查

| 模板             | 核心内容                                                             |
|:-------------- |:---------------------------------------------------------------- |
| **研究prompt**   | `你是一名[角色]。研究[主题]。要求：中文、法规标注文号+日期、正文[N]引用、文末##参考文献、输出后check.sh。`  |
| **交叉审核prompt** | `你是[角色A]。审核[角色B]报告。维度：数字交叉验证/专业互补/实操可行/矛盾发现。输出：🔗一致 ⚠️需澄清 💡建议`  |
| **编辑清单**       | 格式（标题/单#标题/无代码块/表格）→ 数据（数字一致/法规准确/引用对应）→ 逻辑（无矛盾/无遗漏）→ 跨报告一致（终审时） |

## 防坑速查

| 坑               | 预防                      |
|:--------------- |:----------------------- |
| 产出没落盘           | 阶段1完成后立即Write；自查检查文件存在  |
| 法规版本不统一         | 阶段1约定统一版本；编辑审核时检查一致性    |
| 数据口径矛盾          | 辩论前做跨报告口径扫描             |
| 方向性错误（不熟悉的法规体系） | 设定中增加反例警示；编辑首轮重点核查术语和方向 |
| 算术计算偏差          | 涉及计算须标注中间步骤；编辑验算关键结果    |
| 同文件内部自相矛盾       | 编辑审核增加内部一致性维度           |
| 交叉审核意见未落盘       | 完成即写入`交叉审核/`目录，再转交被审核方  |
